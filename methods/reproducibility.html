METHOD 03 / RECORDS & REPRODUCIBILITY

建立能被重做的研究记录

把原始输入、处理步骤、代码环境和输出连起来，先让未来的自己能够从头重做，再让他人独立检查。

本文目录1. 可复现从保留输入开始2. 让文件结构表达数据流3. 用数据字典消除隐含知识4. 代码、参数和运行记录5. 做一次从空目录开始的复现6. 完成标准与下载
开始前：能整理文件与表格；知道自己的数据来自实验、公开资料还是模拟

1. 可复现从保留输入开始

一张图或一个最终数值无法说明它如何产生。可复现记录需要连接问题、输入、转换、分析和输出：输入来自哪里，单位是什么，用哪个脚本和参数，得到哪个结果，哪些步骤仍需人工操作。应在采集或生成数据时开始记录，事后从记忆补写会丢失关键选择。

教学单摆案例使用合成数据，应同时保留生成规则、生成程序与数据文件。固定噪声序列或随机种子能使示例重做，但固定种子本身并不证明模型正确，也不代表模拟数据具有真实实验中的全部误差来源。

2. 让文件结构表达数据流

project/
  README.md
  data/raw/          # 原始记录或教学合成输入
  data/processed/    # 由脚本产生的中间表
  scripts/           # 处理与分析代码
  results/           # 图、表、拟合与诊断
  notes/             # 决策、异常与运行记录

目录名称只是示例，核心是避免覆盖原始记录。原始输入修正时保留原版、修正理由与版本；处理脚本读取输入再写新文件，尽量不手工编辑中间结果。敏感数据可以有受限访问记录，可复现不意味着必须无条件公开所有数据。

3. 用数据字典消除隐含知识

每个字段记录名称、含义、单位、允许范围、缺失值约定与来源。例如 length_m 应说明是悬点到摆球质心的长度，而非绳长；period_s 应说明是单次周期还是多周期总时间换算值。列名带单位很有用，但不能替代测量定义。

若实验记录的是 N 次摆动总时间，保留 N 与原始总时间，处理时再计算周期。不要只留下四舍五入后的平均周期。若教学CSV直接给出周期，也应说明它由什么确定规则产生，以及长度是否被当作无误差输入。

4. 代码、参数和运行记录

  1. 在 README 写明运行目录、命令、软件版本、输入和预期输出；仅使用标准库也要说明 Python 版本要求。
  2. 记录拟合是否包含截距、剔除数据规则、单位换算和图表设置。将参数集中保存，不依赖交互环境里看不见的历史状态。
  3. 用版本控制保存有意义的代码与文档改动；提交说明写出原因，生成数据和大文件采用适合项目的存储方式。
  4. 运行时记录时间、代码版本、参数、成功或失败结果；随机方法记录种子及库版本，必要时说明平台差异。
  5. 检验量纲、极限、解析基准与数值收敛。脚本正常退出只说明执行成功，不等于科学结论正确。

5. 做一次从空目录开始的复现

复制项目到新的位置，按 README 从输入运行到报告，不使用原环境中未声明的文件。检查是否产生预期字段、行数、拟合参数与残差；数值输出用合理容差比较，而非不加说明地要求所有平台最后一位都相同。若依赖需要安装，锁定版本并保留来源；不要为跑通而跳过校验。

请同伴按说明重做，并记录遇到的歧义。未成功时先判断是缺输入、环境差异、实现错误还是模型选择不同；保留失败记录和修正过程。只有重做了核心步骤，才能把“文件已上传”升级为“过程已复现”。

6. 完成标准与下载

完成本单元时，应交付：问题说明、原始输入、数据字典、分析代码、环境说明、运行命令、结果与局限；他人不需要口头补充就能找到核心输出。分享之前确认数据、图像和代码的来源与许可，未公开材料不随意放进公共仓库。

下载研究日志模板和数据字典模板，再用单摆合成数据案例练习。记录与共享资料可参考 OSF 官方帮助；采用其中功能前仍需理解本项目的版本、权限和存档要求。
